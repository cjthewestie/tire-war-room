每天

工作流程

git pull→開 issue→開分支→改程式→跑測試→push→開 PR→別人看過→merge

不要直接 push 到 main。

ISSUE

每件工作先開 issue

  • Issues → New issue → 選「任務」或「Bug」
  • 標題：[座位] 一句話，貼標籤 seat-A～seat-D
  • 寫清楚「做完的樣子」：一個可以檢查的條件
gh issue create --title "[C] 指揮官 JSON 錯誤時重問一次" \
  --label seat-C --assignee @me
分支 · COMMIT · PR

改程式的三個格式

# 分支：座位/issue號-簡述
git switch -c c/12-reask-commander
# commit：類型(範圍): 做了什麼
git commit -m "feat(agent): 指揮官 JSON 錯誤時重問一次"
# 測試全綠後
uv run pytest -q
git push -u origin c/12-reask-commander
gh pr create --fill        # 說明寫 Closes #12
座位

只改自己座位的資料夾

座位角色負責
A隊長・主講docs/、README.md
B邊緣部署deploy/、bench/
CAgent・後端warroom/agent、api、tools、schedule、kb
D展示・前端web/、docs/screenshots/
共用改前先講warroom/contracts.py ＋ web/src/contracts.ts
規範

五條一定要遵守

  1. 不加任何能動到機台的工具；寫入一定經過動作把關
  2. 安全核心不碰 LLM
  3. 不提交 data/runtime/、.env、金鑰、PIN
  4. 只寫量測過的數字，標明 Mac 還是 DGX Spark
  5. main 永遠能跑：全部測試綠才 merge
完成

有問題就開 issue
